# 插件常见场景验收

只验证实际插件，不把 P1–P4 原型结果替代成品验收。不主动扩展强杀/全面并发/多重故障；PHP 改动先 php -l，测试后记录环境和结果即可。

## 首版主流程

1. 在本任务本地普通单站安装/启用插件，管理员可进入一个备份页，普通用户不能操作或下载。
2. 正常备份导出：包含自建目录/中文文档/空目录/零字节文件和数据库全部表；隐藏项按说明排除。
3. 用已确认精确规则检查缓存/备份两个类别开关，不误删名称类似的自建数据。
4. 检查一个超过 512 MiB 的单文件可分块分包，独立解包重组后大小/完整 SHA256 与源相等；其他正常文件逐一比对。
5. 全表 SQL 恢复到一次性测试库，表集合、结构/索引及数据比对相同；包含历史前缀、自建表和空表。不在真实源库执行恢复。
6. 临时维护正常完成可重新访问；搬家完成仍显示维护，取消备份不解除，明确取消搬家才恢复。复制材料不让目标继承控制状态。
7. 下载按完整材料展示，文字为已发起。存在可下载的完整备份时才展示直链提醒。自动推进时显示进度和取消，关页不再推进，返回暂停任务时才显示继续按钮。失败显示明确原因。
8. 从插件列表的「备份」进入，执行期间验证阶段、表计数或分包信息在同一页面更新。网络请求中断后在当前页可继续，成功后一次导航到备份列表。批次请求缺少有效 nonce 时必须被拒绝。

## 少量直接失败

不支持的布局/链接、必要读写失败、工作目录不可安全使用时有明确拒绝或失败；不生成虚假完整材料。只测与当次模块直接相关的常见情况。

本阶段不测试面板上传恢复、证书、DNS，不新增完整恢复器模拟这些功能。插件备份通过后，面板开发完成再做一次正常整站恢复验收。

## 站内工作目录验收

- 在普通站点开始备份，验证自动建随机目录及保护文件、实际备份与后台下载、精确排除工作目录。
- 禁止 WordPress HTTP 回环并让测试服务器忽略目录保护文件。开始和继续均能推进，后台提示直链访问风险及如何为工作目录设置 Nginx 禁访。

已在隔离的 WordPress 7.1.5、Apache 2.4.67 环境通过以上站内目录验收。重组比对 4,272 个路径、25 个 ZIP 和 15 张表，详见[任务卡](work/active/2026-11-22-plugin-development.md)。

## 第三方目录自动排除验收

- 预览列出实际匹配并标注插件。直接点击开始，命中的缓存和备份目录均默认跳过。
- 关闭单个类别后，当次纳入该类别，另一类仍按规则排除。相似但未确认归属的目录、配置目录和混放用户材料的自定义目录保留。
- 对实际备份逐项核对排除索引、文件路径集合、块及 ZIP 校验值、独立重组后的文件和数据库数据。

## 缓存加载文件

标准内容路径的 `object-cache.php` 和 `advanced-cache.php` 同时存在并配置 Redis 时，仍能生成完整备份。两文件仅出现在排除索引、不含文件块，源文件保持原样。其他位置的同名文件照常备份。`wp-content/db.php` 继续在预检拒绝。

## 本地存储流程验收

隔离站禁止回环且忽略 `.htaccess` 时仍成功启动、继续及完成整套备份。单独使用 Nginx 复核示例规则，备份路径返回 403，普通静态文件可正常访问。重组与后台下载验证见[任务卡](work/active/2026-11-22-plugin-development.md)。

## 列表与分包数量

创建页显示进行中和未完成任务，下载入口、备份大小及直链提醒仅在备份列表显示。新任务成功后进入列表，旧版完整备份仍可下载。正常大小的站点应按原始载荷而不是 HTTP 请求次数分包，在已积累未压缩文件块时暂停和继续后仍可逐项重组验证。

## 可选分包与下载

选择不同分包档位时，以同一隔离站验证实际包数及原始载荷不超过选定预算。完成后逐份下载和整套 TAR 均可获取相同材料，归档可用标准 TAR 工具解开。无效 nonce 及内部状态文件的下载请求继续被拒绝。
