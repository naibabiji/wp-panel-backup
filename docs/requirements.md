## U：已确认的备份体验

- 独立插件 WP PANEL Backup / wp-panel-backup。首版 1.0.0，默认中文界面，GPL-2.0-or-later。WordPress.org 提交审核及发布方式另行安排。
- 源站最低 WordPress 6.5、PHP 7.0，实际 WordPress 与 PHP 组合仍须相容。支持根目录安装的普通单站，home/siteurl 一致，使用标准 HTTP/HTTPS 端口。子目录、Multisite、非标准端口或国际化域名在预检拒绝。
- 递归备份网站根目录的文件、自建目录/文档和空目录，不局限 WordPress 默认目录；隐藏文件/目录默认排除并如实说明。
- 缓存、其他备份插件的备份目录可分别勾选排除，默认勾选；只对明确识别的精确路径生效，不按 cache/backup 名称猜用途，不排除整个 uploads；内置一组主流备份和缓存插件的目录识别，预览显示实际命中。
- 根内容目录的 `wp-content/object-cache.php` 和 `wp-content/advanced-cache.php` 固定排除，预检展示存在的路径，索引记录排除原因。备份过程保留源文件，目标重新配置缓存。其他位置的同名文件照常备份。
- 备份范围内链接、硬链接、特殊文件、外置内容布局首版预检拒绝，不能静默漏备后称成功。
- 导出当前连接数据库全部表，包括历史前缀和自建表，不筛归属；记录实际活动前缀供恢复配置使用，不等于按此前缀筛表。
- 首版要求全部表为 InnoDB，拒绝视图、触发器、事件、存储过程与存储函数。无主键大表和分批一致性的宿主边界见待定事项，导出失败须明确提示。
- 生成普通独立 ZIP 分包，单个大文件允许分块跨包，不继承面板间搬家 512 MiB 限制；参数和格式 schema 尚未冻结。
- 正常备份（默认）、临时维护备份、搬家备份互斥。游客维护时看到提示；管理员保留登录/备份控制/下载/取消/解除入口，不追求所有后台/CLI/外部 SQL 绝对停写。
- 临时维护正常结束后解除本任务维护；搬家模式成功、失败、取消备份、关页或超时都不自动恢复旧站写入，只有明确取消搬家才解除；不解除别的工具原有维护。
- 点击「开始备份」后自动预检，站点、文件、数据库及工作目录检查通过后才开始导出。
- 开始备份后，进度区提示大型站点可能需要较长时间。阶段标题下固定一行显示已写入的 SQL 大小和已处理的站点文件原始大小，随成功保存的批次更新。
- 备份页检测源站 PHP。主、次版本与 WP PANEL 的 PHP 8.3 不同时，在开始备份前提示恢复后可能出现运行错误，并可通过目标站 PHP 日志和面板 AI 开发功能辅助排查。版本差异本身不阻止导出。
- 生成由打开的管理页通过后台请求逐批推进，执行期间只更新进度区域。等待批次时显示旋转圆环，启用减少动态效果时显示静态圆环。离开页面后不调度新批次，返回或网络中断后可继续。完成后进入备份列表。不承诺离页后台生成、任意 SQL 断点重放或原子文件/数据库快照。
- 插件列表的快捷入口显示「备份」。创建、执行进度、状态提示及列表使用统一后台样式，下载直链说明仅在有成品的列表中显示。
- 「备份列表」与创建及推进任务的页面分开，按整套组织，提供单文件 TAR 和逐份下载，标“已发起下载”，不声称浏览器已经保存；后续上传端验证全部材料。
- 源端保留最近 2 套完整备份，每套从完成时间起保留最多 7 天，末套同样到期。半成品从最后有效推进起保留 7 天。查询不延期，清理与批次执行互斥，新完整备份成功后才轮转旧完整包。
- 默认自动建立站内备份目录，生成 Apache / IIS 禁访文件和防目录列表用的默认索引。服务器是否禁止备份直读由主机配置决定，插件提示不要泄露文件 URL，并提供 Nginx 禁访示例。普通 ZIP 下载名称保持原样，不加密备份。
- 源域名、协议与表前缀写入元数据，目标不可编辑域名；HTTPS 保持原协议。证书/新身份/数据库凭据由面板处理，不是插件职责。

## R：正常准确性和维护边界

- 未读文件、导出/写入/压缩关闭失败不能得到完成清单；先全部写入校验，再公布完整备份。
- 每包和完整文件有内容校验；CRC、文件存在、首页 200 不等于完整准确。
- 控制状态不得仅以域名判断本机，不能复制到目标后自动维持维护或续跑源任务。工作文件和自身输出必须明确排除。
- 备份与后台下载入口必须有权限及请求校验。匿名 HTTP 直读由服务器配置控制，后台不提供公开下载 URL。
- 原 wp-config 中已识别必要密钥无法迁移时提前提示/拒绝；URL 常量与数据库冲突拒绝，其余依赖按支持清单处理，不承诺所有插件自动识别。
- 一般维护提示按最小实现；异常后管理员修改配置等情况如实记录，不因此新增全局停写保护框架。

## T/Q：开发前逐模块收敛

参见 [待定事项](pending-decisions.md)与[格式候选](backup-format.md)。P3 的 16 MiB 块、64 MiB 载荷、4 MiB 上传片只是原型参数；不能复制成用户已确认默认值。上传片是面板实现细节，不要求源插件额外实现上传器。

## 明确不做

恢复/覆盖网站、自动改域名、序列化搜索替换、源站直传、Assistant 接入、云存储、定时/增量备份、加密备份、多格式引擎、全站绝对停写。兼容旧站不等于承诺任意主机/插件都支持。

## 2026-11-22 确认的首版导出决策

- 两类第三方精确排除规则默认启用，可按类别临时关闭。使用范围见目录规则文档。隐藏项按已确认规则排除。
- 原根目录 `wp-config.php` 作为私有参考。原数据库凭据由目标重新配置。已识别、无法安全迁移的业务依赖预检拒绝。有效 URL 与数据库冲突、自定义数据库 drop-in 拒绝。
- 首版数据库支持 InnoDB。有主键按键分批，无主键一个请求流式导出。超时或读取失败显示涉事表，整套不完成。正常模式仍无跨请求快照保证。
- 使用 ZipArchive，文件块最多 16 MiB。新任务可选择每包 128 MiB、512 MiB 或 1 GiB 的原始载荷，默认 512 MiB。JSON 清单、逐行 JSON 文件索引、SQL 顺序重组和 SHA-256 继续使用，整套 TAR 为可选下载封装。
- 站内默认目录为 `wp-content/wp-panel-backup-storage-<32位随机十六进制>`，每个任务另用独立随机目录。启用、开始备份无需编辑 `wp-config.php`；插件创建目录和保护文件后直接执行备份，启动及继续均不发送匿名自检请求。仅支持自动管理的站内目录。
- 普通插件钩子维护。临时维护成功时自动解除，失败保留管理员手动解除入口。搬家维护仅由管理员明确取消搬家解除。
- 半成品从最后有效推进起保留 7 天，完整备份从完成起保留 7 天（包括最后一套），由后续后台操作清理，执行中跳过。完整套数只在新成功后轮转。
