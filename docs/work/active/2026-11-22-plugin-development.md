## 阶段 1 已完成：入口与基础预检

- 可激活的单文件入口，通过“工具 → WP PANEL Backup”提供中文管理页。页面由 `manage_options` 保护，POST 在后台输出前验证专用 nonce。
- 检查普通根目录单站、标准端口、非国际化域名、两个有效地址与数据库原值、站点文档根和内容位置。
- 递归检查文件可读性、软链接、硬链接和特殊文件，跳过隐藏项。枚举当前连接数据库可见表及不支持对象，读取失败返回明确提示。
- 页面显示“基础检查通过”及文件/可见表计数。数据库元数据查询会受账号权限影响，正式导出前仍须验证有足够权限证明对象和表清单覆盖完整。预检目前在一次管理页请求中完成扫描，大站分批与导出阶段衔接；没有生成材料或进入维护的入口。

## 阶段 1 验证

- 环境：缓存镜像 `wordpress:7.0-php8.3-apache`（WordPress 7.0、PHP 8.3.31）和 `mariadb:11.8`。临时 Compose 项目 `wp-panel-backup-stage` 无宿主端口，测试域名为容器内映射的 `http://backup.test`；配置和一次性夹具在 `/tmp/wp-panel-backup-stage`，数据在容器 tmpfs。
- 实际 WordPress 激活确认；管理员 GET 页面成功，正常 POST 报告扫描 3956 个文件、12 张可见表（含合成中文文件和空目录夹具，隐藏链接被跳过）。
- Subscriber 访问和无效 nonce POST 均返回 403；可见软链接、自建数据库视图和子目录地址分别返回预期提示。
- 所有新增 PHP 均通过 `php -l`。此阶段的计数仅是预检证据，实际备份路径集合、SHA-256 及全表结构和数据比对尚未执行。

## 阶段 2 已完成：正常备份导出与准确性

- 使用已核对的独占私有目录、原生文件锁和分批状态，管理员页面推进正常导出。文件索引记录全部目录、文件、分块及隐藏排除项。源配置作为私有文件，SQL 和 ZIP 受同一任务完成状态约束。
- 数据库使用原生 mysqli 无缓冲读取。有主键使用有序键游标，单批 512 行或约 4 MiB SQL 后推进；无主键单次读取。当前按显式库级授权佐证对象可见性，未实测通过角色取得的权限。
- 通过实际 WordPress 登录和后台 POST 生成开发产物。空间隔离的 MariaDB 临时库导入重组 SQL 后，15 张表的完整 `SHOW CREATE TABLE`（含索引）及逐行数据相同。覆盖 601 行复合主键、历史前缀、自建无主键和空表、NULL、重复行、emoji、Latin-1、二进制、位字段及长字段。
- 独立 Python 校验器读取 26 个 ZIP 和文件索引，校验每包、每块和完整文件，并与源站 4,425 个文件和目录路径比对；覆盖 513 MiB 单文件跨 9 包、零字节文件、空目录、隐藏项和自建同名缓存目录。校验脚本和合成材料只在 `/tmp/wp-panel-backup-stage`。
- 验证中发现长字段经重复组正则会触发 PCRE 长度限制，已换为逐字节十六进制校验并重跑通过。整体扫描和单个文件完整哈希仍各在一次请求中，大站单次请求资源上限需如实反馈。
- 接下来实现维护、取消、受控下载和轮转。阶段 2 实测版本仍是 WordPress 7.0 / PHP 8.3.31 / MariaDB 11.8。

## 阶段 3 已完成：三种模式、下载和材料清理

- 增加普通 WordPress 维护钩子，保留后台备份控制和登录。工作区绑定 WordPress 根目录路径及设备号与 inode；任务和维护记录留在私有工作区，备份不携带它们。
- 完成管理员受控下载、已发起标记、取消与删除入口，清理以任务锁串行执行。七天到期的完整包立即不可下载，后续管理操作清除材料；新成功后仅保留最近两套。取消搬家和手动结束临时维护独立于过期清理。
- 实际 HTTP 验证：正常访客可访问；临时维护提示 503、登录及后台可用，停止提交推进后任务阶段保持，恢复推进成功后站点回到 200。搬家完成以及取消备份后均为 503，明确取消搬家后恢复 200。
- 实际下载分别核对清单、索引和 ZIP 响应与磁盘字节；无效 nonce 返回 403，内部 job.json 返回 404，普通用户无法下载。验证新完成后只保留两套，通过调整合成任务时间验证末套完整备份及半成品由后台清理。
- 当前整合版正常备份复核：4,426 个文件和目录路径，26 个 ZIP；513 MiB 大文件跨 9 包。校验全部包、块和完整文件的 SHA-256，并逐项比对源文件与重组结果。重组 SQL 导入新的临时 MariaDB 库，15 张表的结构、索引和数据相同。
- 直接失败验证：站点根内的工作目录和非 InnoDB 表在启动时被拒绝，显示具体原因。所有 PHP 和批次 JavaScript 通过语法检查。任务推进使用实际 HTTP 请求验证，未进行浏览器 UI 自动化、强杀或全面并发测试。
- 局域网业务站没有改动。正式兼容范围、格式冻结和面板恢复留待复审。

### 站内工作目录验证与交付

- 隔离站为 WordPress 7.1.5、PHP 8.3.31、Apache 2.4.67、MariaDB 11.8。测试未使用站外目录常量。关闭 Apache 目录级规则时，首次开始返回明确错误，未写入任务与备份数据；保护失效后点击继续也被拒绝，任务状态与 SQL 输出保持原样。恢复规则后继续完成实际备份。
- 已验证真正的 ZIP 路径匿名返回 403；后台授权下载与落盘 ZIP 逐字节一致。索引记录工作目录排除项。普通包名保持原样。搬家模式下取消备份仍保留维护，明确取消搬家才开放。
- 独立重组核对了 4,272 个路径、25 个 ZIP 和全部文件 SHA-256。513 MiB 单文件跨 9 包。SQL 导入临时库后，15 张表的结构、索引和数据逐项一致。
- 站外目录支持已移除，旧文件不迁移或删除。测试包只含 8 个运行文件，输出 `dist/wp-panel-backup-0.0.0-dev-auto-storage.zip`。Nginx 与实际局域网站点未联调，本轮不提交、发布或部署。
