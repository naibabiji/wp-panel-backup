# 备份交换格式 v1

- 首发约定：用户已确认 WP PANEL Backup 1.0.0 首发冻结当前 v1。插件与 WP Panel 候选已通过真实备份和局域网恢复验收。首发仍待用户确认发布。
- 文件格式由生产者维护，消费端关联 [WP Panel 关系](integrations/wp-panel.md)。不兼容的更改需要新格式版本和两端兼容方案。

## 材料及组成

一套材料包含 `manifest.json`、`files.ndjson` 及连续编号的独立 ZIP 分包。可逐份下载，也可下载整套 USTAR。备份包含完整的文件/目录索引和全库 SQL，大文件可跨包。未完成材料不可恢复。

| 内容 | 用途 |
| --- | --- |
| 清单 | 格式标识、备份 ID、完成标志、源地址与活动前缀、表清单、排除报告及各材料名称、大小和 SHA-256 |
| 文件索引 | UTF-8 逐行记录，描述路径、目录、排除规则、块引用、偏移及摘要 |
| 数据内容 | 文件和数据库 SQL 的内容块。SQL 完整重组后交面板导入 |
| 包 | 普通独立 ZIP，块按文件索引顺序拼接 |

## 契约与验证

- 插件是生产者；独立检查脚本可以读取材料验证准确性，WP Panel 负责消费和恢复。
- 发布完成清单前检查 SQL/文件/所有包生成成功和校验；错误不能只记录日志仍显示成功。
- 面板在创建资源前验证材料齐全、同一备份、版本、内容哈希、路径、容量与布局。
- 面板从完整 SQL 输入一次调用既有 root/mysql CLI 及原过滤，不增加驱动/SQL 正向解析器。
- 活动前缀仅是目标配置元数据，不用于筛选数据库表。
- 源维护标记、运行任务授权、旧面板身份不在目标重新生效。旧配置如何携带敏感内容/排除仍以需求和配置支持表为准，不能因文件在包内就执行旧配置。
- v1 保留首发前已经验收的材料标识和读取规则。压缩等级等实现参数可以在 v1 消费端已支持的范围内调整。

## 记录格式

清单使用固定的 `magic: wp-panel-backup-development` 及 `format_version: 1`。沿用该标识，以兼容此前已生成的有效 v1 备份。

- `manifest.json` 包含 `id`、`complete`、`mode`、`completed_at`、`source`（`home`、`siteurl`、`prefix`）、`tables`（`name`、`rows`）、`exclusions`、`index` 和 `packages`。材料引用记录 `name`、`size` 和 `sha256`。
- `files.ndjson` 是 UTF-8 的逐行 JSON。记录类型按 `kind` 区分为 `directory`、`excluded`、`block`、`file` 和 `sql`。排除记录含 `path` 和 `reason`。文件和 SQL 结束记录含 `path`、`size`、`sha256`；零字节文件只有结束记录。
- 块记录含 `target`（`file` 或 `sql`）、`path`、`package`、`member`、`offset`、`length`、`sha256`。同一目标按偏移顺序拼接。SQL 的逻辑路径 `database.sql` 与网站同名文件分开识别。原站 `wp-config.php` 以原路径记录，消费端只作配置参考。
- 2026-11-23：同表同列的普通 SQL 行合并为标准多行 INSERT，每条最多 256 行和 4 MiB（含语句头、行间隔和末尾）。超出批次预算的单行独立写入，仍取决于目标 MariaDB 的单语句限制。每步写完再保存既有偏移。SQL 块、清单、分包和格式版本保持兼容，面板普通恢复和恢复建站共用同一导入核心。
- 分包文件名为 `part-00001.zip` 起的连续序号。各自是普通独立 ZIP，成员位置由索引指向。块最多 16 MiB。新任务的单包原始载荷可选 128 MiB、512 MiB 或 1 GiB，默认 512 MiB。已有任务使用原预算。源端可以跨多个 HTTP 请求累积同一包。达到载荷预算或完成扫描后写出分包，极多微小文件时也受单包条目数上限约束。成品 ZIP 实际字节取决于压缩。能按条目设置压缩方式时，确认格式的 JPEG、WebP、AVIF 块用标准 ZIP STORE，GIF 用低级别 DEFLATE。其他材料沿用默认方式。清单、块与完整文件摘要及读取规则保持不变。
- 全套材料需要单独的清单和索引。ZIP 不包含本地任务状态、工作目录、维护标记或下载状态。
- 自动站内工作目录仅在索引中以 `kind: excluded`、`reason: workspace` 记录。随机磁盘目录不影响用户下载的文件名。
- 整套 TAR 的浏览器下载名使用源站域名、站点时区完成时间和备份 ID 前 8 位。下载名用于辨认备份，材料识别继续使用 TAR 内的清单、索引及分包记录。
- 第三方目录的 `excluded` 记录使用 `reason: cache` 或 `reason: backups`，另附归属插件 `plugin`。该目录及其内容不包含在文件块中。
- 标准缓存加载文件的 `excluded` 记录使用 `reason: cache-drop-in`。源站 Redis 配置若存在于 `wp-config.php`，仅随配置参考保留，恢复端需使用目标站配置。

### 整套单文件下载

整套下载是按需流式生成的标准 USTAR 文件。顶层包含相同的 `manifest.json`、`files.ndjson` 和全部原始 ZIP 分包，每份内容与逐份下载逐字节一致。没有目录、链接或额外控制文件。分包的哈希校验沿用清单，源端不保存额外 TAR 副本。面板直接读取外层 TAR 的成员，逐份下载与整包使用同一套校验和恢复逻辑。
